# PARTE I — CONTEXTO E REGRAS

## 1. Identidade do projeto

**audio-suite** (`github.com/danzeroum/audio-suite`, branch `main`) é uma CLI Python de análise acústica objetiva para QC de áudio *evidence-grade* — broadcast, MAM/DAM, perícia, pipelines de IA de voz. Posicionamento-alvo:

> *"Evidence-grade audio QC: deterministic, signed, standards-verified."*

| Camada | Estado atual (commit `b2b5f72`) |
|---|---|
| Analyzers | **35 registrados** (loudness BS.1770-4, true_peak, clipping, glitch, LRA R128, transient, phase, spatial_coherence, goniometer, multichannel_layout 5.1/7.1, stem_sep SI-SDR, acoustic_context RT60, deepfake opt-in, enf_phase experimental, acoustic_fingerprint 256-bit, metadata_schema_validator EBUCore/Dublin Core, e outros) — cada um com contrato `ID/NAME/VERSION/METHOD/DEFAULT_LIMITATIONS` |
| Motor | `engine.py` (descoberta, TOCTOU), `policy.py` (perfis YAML + lockfile), `cartridge.py` (plugins externos) |
| Evidência | `bundle.py` (schema URN, fingerprint de medição, quantização), `security/` (Ed25519 em 3 modos, redação PII), `audit.py` (JSONL append-only com hash-chain + self-check) |
| Outputs | JSON, SARIF 2.1.0, HTML (WCAG), CSV |
| Entrega | `action.yml` (GitHub Action com upload SARIF), Dockerfile (python:3.12-slim, non-root), CI: ruff + mypy + pip-audit + pytest 3.11/3.12/3.13 |
| Testes | ~203 passando (T01–T110, CT01–CT15, EV01–EV12, SG01–SG12, IN01–IN15), cobertura declarada 86%, **23 fixtures determinísticas com manifest SHA-256 já existentes** |
| Dependências runtime | **numpy ≥ 1.26 — única. Isso é um ativo de adoção e não pode ser destruído** |
| Maturidade de repo | Construído em ~12 commits no mesmo dia; sem tags, sem releases, sem PyPI; `pyproject.toml` em 0.1.0 |

## 2. Regras invioláveis (nenhuma implementação pode quebrá-las)

| Regra | Enunciado |
|---|---|
| **R1** | Descritores subjetivos (centroid, BPM, tonalidade, timbre→gênero) **nunca** causam falha automática — apenas `observation`/`needs_review` |
| **R2** | **Sem referência, sem métrica full-reference** — proxies são explícitos e rotulados |
| **R4** | ML **sempre opt-in** (cartridge/extra) — nada de modelo bundled no core |
| **R8** | **Nunca concluir autenticidade** — deepfake/ENF/similares terminam sempre em `needs_review` |

**Contrato estrutural imutável:** modelo de 6 status (`PASS / WARNING / FAIL / NEEDS_REVIEW / NOT_APPLICABLE / INDETERMINATE`) + exit codes (`0/1/2/3/64`). Toda funcionalidade nova é adaptada a este modelo — não se introduz `pass/fail` binário.

## 3. Política de dependências (não-negociável)

- **Runtime core:** apenas numpy. Qualquer capacidade que exija outra lib (pystoi, pesq, librosa, sklearn, torch, ffmpeg) entra como:
  - **extra opcional** (`audio-suite[stoi]`, `[pesq]`, `[visqol]`, `[ai-detect]`, `[listening]`), com degradação elegante e testada quando o extra não está instalado; **ou**
  - **cartridge externo** (opt-in);
  - **ou geração offline de fixtures** no `gen_fixtures.py` (deps de dev aceitáveis apenas aí — ex.: time-stretch/pitch-shift dos metamórficos).
- Se houver caminho numpy puro (DRn, DC offset, quantização, reversal, ruído), **é o caminho obrigatório**.
